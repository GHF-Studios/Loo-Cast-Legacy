Global Options:
	--verbose
		show operation planning, diagnostics, logs, historical context, and live progress detail

	--yes
		accept non-destructive interactive prompts

	--force
		allow destructive mutation when destructive mutation is explicit, acceptable, and domain-valid
		allow risk-bearing operations when the command explicitly supports forcing that risk
		never means "ignore linker/build/runtime impossibility"
		never means "blindly pick newest dependency version and hope"
		never means "bypass release-mode dependency rules"

	--strict
		reject add/remove/select/unselect mutations that would leave an authored composition invalid

	--keep-unused-versions
		keep old unused installed dependency/content versions after install/update/lock/repair cleanup

Composition State Terms:
	installed content exists locally
	added content is a member of a composition
	selected content is active inside that composition
	unselected content may remain present as an inactive alternative
	resolved content is the effective graph after selections, nesting, versions, and invariants are applied
	validated content is content whose current graph satisfies built-in and author-defined invariants


Lock Targets:
	packagepack


Runtime Resolution:
	resolve constructs the effective graph in memory
	resolve does not write a lockfile
	lock writes the selected/effective packagepack graph as a persistent artifact


Built-In Resolved Invariants:
	exactly one effective engine
	exactly one effective game
	selected/resolved game must target the selected/resolved engine
	resolved graph must satisfy declared parent/target requirements
	resolved graph must satisfy declared version requirements
	resolved graph must not contain invalid cycles
	resolved graph must not contain hard conflicts


Important Update Rule:
	packagepack is the normal user-updated experience boundary

	Updating packagepack:
		valid launcher workflow

	Updating engine/game/mod content outside packagepack:
		not a normal user workflow
		implies authoring/local fork semantics
		may invalidate or fork packagepack state
		belongs primarily to SDK or modpack-author/developer flows

	Old unused dependency/content versions:
		pruned by default after successful update, lock, repair, or cleanup
		kept when --keep-unused-versions is passed
		require migration when they carry config/data/state
		abort by default when required migration is missing
		may be discarded only through explicit user choice or a supported forced operation
