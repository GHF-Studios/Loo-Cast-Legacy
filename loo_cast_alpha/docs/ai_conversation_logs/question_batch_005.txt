Question Batch 005: Vapor SDK / Capability / Rhai / Steam Distribution Redesign Pass

NOTE: This is a full replacement for the previous two versions of batch 005.
The first version was too broad and dragged USF/worldmodel/experimental ontology into the active thread.
The second version overcorrected by treating Capabilities and Rhai as merely platform-adjacent metadata concerns.
This rebuilt version keeps concrete engine/game internals and USF out of scope, but treats Capabilities and Rhai as foundational Vapor substrate.

Explicit out-of-scope for this batch:

- Concrete first-party engine details.
- Concrete first-party game details.
- USF, worldmodel, chunks, metrics, phenomena, zones, scales, rendering, save/load, gameplay simulation, and Phase 4-specific architecture.
- Any attempt to define how a particular engine or game implements its internal runtime beyond the minimum Vapor-facing contracts required for launch/composition/distribution.

Explicitly in-scope for this batch:

- Vapor as a Steam-exclusive SDK, launcher, distribution, identity, modding, composition, and validation ecosystem.
- Capability semantics as a foundational engine/game-independent Vapor mechanism.
- Rhai declarations as foundational engine/game-independent authored asset/capability metadata and authoring substrate.
- Generic Engine and Game roles only as Vapor product-stack slots/fixtures.
- Packagepack, Enginepack, Gamepack, Modpack, Engine Mod, Game Mod, Extension Mod, and related pack/artifact vocabulary.
- Steam identity, ownership, Workshop upload/download/install, publishing, local/offline authoring, and diagnostics.
- Phase 3 scope only insofar as it proves Vapor, Capability, Rhai, launcher, SDK, and Steam distribution seams.
